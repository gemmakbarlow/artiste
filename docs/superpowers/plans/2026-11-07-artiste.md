# Artiste Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Artiste, a landscape SwiftUI iPad/iPhone game in which a child drags arrow and paint actions into slots, taps Play, and watches a marker paint a 5×5 grid to match a target picture.

**Architecture:** There are three layers. `Engine/` holds pure, `Sendable` value types and a stateless `Interpreter` that computes a whole run up front. `Game/` holds a `@MainActor @Observable GameViewModel` that plays those steps back with a delay, plus small stores for levels, progress and sound. `Views/` is SwiftUI only, with no game logic. Levels live in `levels.json`. The Xcode project is generated with XcodeGen from `project.yml`, and the generated `.xcodeproj` is committed.

**Tech Stack:** Swift 6.3, SwiftUI, iOS 26 SDK (Xcode 26.5), Swift Testing, XcodeGen (build-time tool only, at `/opt/homebrew/bin/xcodegen`), AudioToolbox system sounds. No third-party runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-07-artiste-design.md`. Read it before starting any task.

## Global Constraints

- Deployment target is **iOS/iPadOS 26.0** (the latest major release available in Xcode 26.5), with no back-deployment.
- Universal app (`TARGETED_DEVICE_FAMILY = 1,2`), **landscape left/right only**.
- **SF Symbols only** for icons. The only image assets are the generated `AppIcon` and `LaunchGlyph` PNGs.
- No third-party runtime dependencies.
- Use **American spelling** in all code, comments and UI copy (color, favorite, gray).
- Exact copy:
  - `Artiste` (title)
  - `A game for Nina, by Mom` (italic subtitle)
  - `Good job!`
  - `Play`
  - `Level N`
  - `You painted them all!` (last-level overlay heading)
- Grid is always 5×5, and the marker starts at `(0,0)` unless the level JSON says otherwise.
- `slotCount = solution.count + 2`, `solution.count ≤ 10`, so there are at most 12 slots.
- Paint color schedule by level id:
  - levels 1–4: `[red, blue]`
  - levels 5–9: `[red, blue, green]`
  - levels 10–15: `[red, blue, green, yellow]`
- Step delay during Play is **0.6 s**.
- Minimum sizes (from §6.2):
  - Tokens and slots: 56 pt on iPad, 44 pt on iPhone
  - Play/Reset buttons: 64 pt tall on iPad, 52 pt on iPhone
- Test command (used throughout; `<Suite>` is a Swift Testing struct name):
  `xcodebuild test -project Artiste.xcodeproj -scheme Artiste -destination 'platform=iOS Simulator,name=iPhone 16e' -only-testing:ArtisteTests/<Suite> -quiet`
- Build command:
  `xcodebuild build -project Artiste.xcodeproj -scheme Artiste -destination 'platform=iOS Simulator,name=iPhone 16e' -quiet`
- After adding any new source file, run `xcodegen generate` before building.
- Shorthand: `(r,c)` in test descriptions below means `Position(row: r, col: c)`.

## Review Focus

1. **Double-tapping Play quickly.** The second tap must be ignored, so only one run happens and steps aren't doubled. Tested in Task 6 (`playIgnoredWhileRunning`).
2. **Leaving the game screen (back button) mid-run.** The run stops, nothing changes the board afterward, and coming back shows a Ready board with the starting canvas. Tested in Task 6 (`cancelRunRestoresReady`).
3. **Dropping or trashing an action while Running or Succeeded.** The drop is ignored, and the slots stay unchanged. Tested in Task 6 (`editingBlockedWhileRunningAndSucceeded`).
4. **Pointless drags.** Dragging a slot onto itself does nothing. A tray token dropped on the trash does nothing. Tested in Task 6 (`selfMoveIsNoOp`) and in the Task 8 drop handler.
5. **Gaps between filled slots.** Empty slots in the middle of the program are skipped, and a program with gaps can still succeed. Tested in Task 3 (`emptySlotsSkipped`) and Task 6 (`gappedProgramSucceeds`).

### Task 6: GameViewModel

**Files:**
- Create: `Artiste/Game/GameViewModel.swift`
- Test: `ArtisteTests/GameViewModelTests.swift`

**Interfaces:**
- Consumes: Tasks 2–5
- Produces:

```swift
enum BoardState: Sendable { case ready, running, failed, succeeded }

@MainActor @Observable final class GameViewModel {
  init(levels: [Level], levelIndex: Int, progress: ProgressStore, sound: SoundPlaying, stepDelay: Duration = .milliseconds(600))
  private(set) var levelIndex: Int
  var level: Level { get }
  private(set) var slots: [Action?]          // count == level.slotCount
  private(set) var canvas: Grid
  private(set) var marker: Position
  private(set) var state: BoardState
  private(set) var activeSlot: Int?
  private(set) var bump: (direction: Direction, count: Int)?  // count increments per bump; drives the wobble animation
  var canEdit: Bool { get }   // state == .ready || state == .failed
  var canPlay: Bool { get }   // state == .ready && slots contains non-nil
  var canReset: Bool { get }  // state == .failed
  var isLastLevel: Bool { get }
  var trayActions: [Action] { get }  // Action.trayActions(palette: level.palette)
  func place(_ action: Action, at slot: Int)   // replace if filled; plays .place
  func move(from: Int, to: Int)                // swap; no-op if from == to
  func clear(slot: Int)                        // plays .trash
  func play() async                            // no-op unless canPlay
  func reset()                                 // only from .failed
  func next()                                  // only from .succeeded and !isLastLevel; loads next level, empty slots
  func cancelRun()                             // stop playback; restore ready board with initial canvas, keep slots
}
```

All edit methods are no-ops when `!canEdit`, or when an index is out of range.

`play()` works like this:
1. Set the state to `.running`.
2. Compute `Interpreter.steps`.
3. For each step: `try await Task.sleep(for: stepDelay)`. If the sleep throws (cancelled), return without touching state, since `cancelRun` owns the cleanup. Otherwise set `activeSlot`, then apply `marker`/`canvas` inside `withAnimation(.spring(duration: 0.35))`, and play `.paint` for paint steps. On `.bumped`, set `bump` and play `.bump`.
4. After the loop: clear `activeSlot`. If no bump happened and `canvas == level.target`, set `.succeeded`, call `progress.markCompleted(level.id)`, and play `.success`. Otherwise set `.failed`.

`cancelRun` has to work out which run is current. Keep a `runID: UUID` that `play` checks after each sleep, and that `cancelRun`/`reset` replace.
